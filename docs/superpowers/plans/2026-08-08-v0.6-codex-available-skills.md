# V0.6.0 Codex Available Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the standalone System section with a read-only Available browser that covers Personal Skills from `~/.agents/skills` and existing Codex System Skills without mixing them into Installed.

**Architecture:** Extend `SkillSource` with a dedicated Available source type, then scan Personal and System as independent read-only locations while excluding System descendants from Agent-copy scans. Keep the existing name + content Hash merge model, preserve every physical source, and let `AppModel` choose the correct Available copy for the active source filter. Reuse the existing three-column SwiftUI structure with a native source menu and context-based read-only detail behavior.

**Tech Stack:** Swift 6.2+, SwiftUI, Observation, Foundation, XCTest, Swift Package Manager, macOS 26+

## Global Constraints

- The source of truth is `docs/superpowers/specs/2026-08-08-v0.6-codex-available-skills-design.md`.
- V0.6.0 includes only Personal (`~/.agents/skills`) and Codex System sources.
- Do not scan `.codex/plugins/cache` and do not add Plugin management.
- Available is read-only: no install, uninstall, delete, update, note editing, or translation generation from that context.
- Library and Installed behavior must remain unchanged.
- Merge only when normalized name and content Hash both match; preserve all physical copies.
- Keep the current settings JSON schema; derive Personal from an injected Home directory and System from Agent Targets that support System Skills.
- Use Apple SwiftUI and SF Symbols only; do not add dependencies or AppKit UI workarounds.
- Existing XCTest targets require a complete Xcode toolchain. Before production edits, run `xcodebuild -version`; if XCTest is unavailable, stop and install/select a complete compatible Xcode. Xcode 27 is not a product requirement, but a complete Xcode installation is required for the existing automated tests.

```swift
public extension SkillPhysicalCopy {
    var availableSource: AvailableSkillSource? {
        guard case .available(let source) = self.source else { return nil }
        return source
    }
}

public var availableSources: Set<AvailableSkillSource> {
    Set(physicalCopies.compactMap(\.availableSource))
}

public var hasAvailableCopy: Bool {
    !availableSources.isEmpty
}

public func availableCopy(preferred source: AvailableSkillSource?) -> SkillPhysicalCopy? {
    if let source,
       let exact = physicalCopies.first(where: { $0.availableSource == source }) {
        return exact
    }
    return physicalCopies.first { $0.availableSource == .personal }
        ?? physicalCopies.first { $0.availableSource == .system }
}
```

```swift
private final class UnreadableDirectoryFileManager: FileManager {
    let unreadableRoot: URL

    init(unreadableRoot: URL) {
        self.unreadableRoot = unreadableRoot.standardizedFileURL
        super.init()
    }

    override func fileExists(atPath path: String) -> Bool {
        path == unreadableRoot.path || super.fileExists(atPath: path)
    }

    override func enumerator(
        at url: URL,
        includingPropertiesForKeys keys: [URLResourceKey]?,
        options mask: FileManager.DirectoryEnumerationOptions = [],
        errorHandler handler: ((URL, any Error) -> Bool)? = nil
    ) -> FileManager.DirectoryEnumerator? {

        return super.enumerator(
            at: url,
            includingPropertiesForKeys: keys,
            options: mask,
            errorHandler: handler
        )
    }
}
```
