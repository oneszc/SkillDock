# V0.6.0 Codex Available Skills Design

## Goal

V0.6.0 增加独立的 `Available` 浏览入口，让用户看见 Codex 当前可发现的 Personal 与 System Skills，同时继续把它们与 SkillDock 管理的 Library 资产、已同步到 Agent 的副本区分开。

本版优先解决“这些 Skill 为什么在 Codex 可用，却没有出现在 SkillDock Installed 中”的认知问题，不接管 Codex 的插件生命周期或可用来源管理。

## Product Scope

V0.6.0 包含：

- 主侧边栏把 `System` 改为 `Available`。
- Available 第一版扫描两类来源：
  - `Personal`：`~/.agents/skills` 下包含 `SKILL.md` 的 Skill 文件夹。
  - `System`：现有 Codex System Skills，继续复用当前 `.codex/skills/.system` 扫描结果。
- Available 第二栏提供 `All Sources / Personal / System` 来源筛选。
- 列表和详情保留来源信息，可显示 `Personal`、`System` 和已合并记录中的 `Agent Copy`。
- 相同名称且内容 Hash 相同的物理副本合并为一个逻辑 Skill，但保留全部物理来源。
- Available 中的 Personal 与 System 均按只读内容浏览处理。

V0.6.0 不包含：

- Plugin Skill 来源接入。
- 扫描 `.codex/plugins/cache`。
- 插件安装、启停、卸载或更新。
- 从 Available 安装、卸载、删除或修改 Skill。
- Personal Skill 的导入、同步或所有权管理。
- 批量同步、后台扫描或自动更新。
- 承诺 Available 数量与 Codex 客户端显示数量永久完全一致。

## Information Architecture

主侧边栏保持三项：

1. `Library`：用户主技能库中的资产。
2. `Installed`：配置的 Agent Targets 中存在的 Skill 副本。
3. `Available`：Codex 当前可发现的只读 Skill 来源，本版包含 Personal 与 System。

旧 `System` 一级入口不再保留。其全部能力迁移到 `Available > System`，不删除或遗漏现有 System Skill。

Available 的第二栏沿用当前 Skill 列表结构，在列表顶部显示来源筛选：

- `All Sources`：显示所有 Personal 和 System 记录。
- `Personal`：只显示至少包含一个 Personal 副本的记录。
- `System`：只显示至少包含一个 System 副本的记录。

来源筛选只在 Available 页面出现。Library 和 Installed 继续使用现有 Agent 筛选，不改变原有行为。

## Source Model

现有 `SkillSource` 需要区分三种所有权语义：

- Library 资产。
- Agent Target 副本。
- Codex Available 来源。

Available 来源第一版包含 `Personal` 与 `System`。它们不能伪装成 Agent Target，否则会被错误计入 Installed、错误显示安装状态，或获得安装与卸载能力。

每个物理副本继续记录来源类型、文件路径、内容 Hash 和只读状态。

Personal 根目录默认为当前用户 Home 下的 `.agents/skills`。目录不存在时返回空结果，不创建目录，也不提示为错误。System 继续使用当前已经验证的 Codex System 来源，不新增第二套扫描规则。

## Merge And Membership Rules

逻辑 Skill 的合并键保持：规范化名称 + 内容 Hash。

- 同名且 Hash 相同：合并为一条记录，保留全部来源。
- 同名但 Hash 不同：显示为不同记录，避免把不同版本伪装成同一个 Skill。
- Available 页面成员资格：记录至少包含一个 Personal 或 System 副本。
- Installed 页面成员资格：记录至少包含一个 Agent Target 副本，与 Available 互不替代并允许重叠。
- Library 页面成员资格：记录至少包含一个 Library 副本，保持现有规则。

进入不同页面时，详情读取对应上下文的物理副本：

- 从 Available 的 Personal 筛选进入时，优先读取 Personal 副本。
- 从 Available 的 System 筛选进入时，读取 System 副本。
- 从 All Sources 进入时，Personal 优先于 System；该顺序只决定展示路径，不改变合并记录中的来源信息。
- 从 Library 或 Installed 进入时，继续使用各自现有的副本选择规则，不被 Available 来源改成只读。

## Interface And Interaction

### Sidebar

- 将 `System` 文案改为 `Available`。
- 使用能表达“可发现内容”的 Apple SF Symbol，保持现有侧边栏尺寸和系统选中样式。
- 数量表示 Personal 与 System 去重后的逻辑 Skill 数，不与 Installed 数量相加。

### Source Filter

- 复用现有第二栏顶部筛选条的系统 Menu 交互和视觉尺寸。
- 标签从 `Agent:` 改为 `Source:`。
- 菜单项为 `All Sources`、`Personal`、`System`。
- 切换来源后，如果当前选中项不再可见，自动选择筛选结果的第一项；结果为空时显示空状态。

### Skill List

- 保持现有列表密度、搜索和选中交互。
- 每条记录显示 Available 来源标签；同一记录有多个来源时可并列显示。
- `Agent Copy` 只表示这条逻辑 Skill 同时存在于某个 Agent Target，不属于 Available 筛选项，也不增加 Available 数量。

### Detail

- 继续展示 Skill 名称、说明、`SKILL.md` 和文件结构。
- 明确显示当前浏览副本的来源与只读状态。
- 允许 `Reveal in Finder` 和 `Copy Path`，因为它们不会修改文件。
- 隐藏或禁用安装、卸载、远程更新、备注编辑和翻译生成等写入型操作。
- 同一逻辑 Skill 在 Library 页面打开时，继续保留 Library 原有可编辑和可操作能力。

## Empty And Error States

- `~/.agents/skills` 不存在：不报错；All Sources 仍展示 System，Personal 筛选显示 `No Personal Skills`。
- 来源目录存在但没有有效 `SKILL.md`：显示对应来源空状态。
- Personal 与 System 均为空：显示 `No Available Skills`，并说明 SkillDock 当前检查 Personal 与 System 两类来源。
- 单个无效 Skill 文件夹：跳过该文件夹，不阻断其他结果；保持现有扫描容错方式。
- 来源读取失败：保留其他成功来源，并显示可理解的刷新错误信息，不把失败来源显示为零个且无解释。

## Counting And Copy

Available 数量采用“名称 + 内容 Hash”去重后的逻辑记录数。界面说明统计范围仅包含：

- Personal：`~/.agents/skills`。
- System：SkillDock 当前识别到的 Codex System Skills。

V0.6.0 不包含 Plugin Skills，因此数量可能少于 Codex 客户端。产品文案不得暗示 SkillDock 已覆盖 Codex 的全部可用能力。

## Compatibility

- 不改变现有设置文件结构，不要求迁移用户配置。
- 不改变 Library、Installed、GitHub 导入、Agent Targets、中文译文和远程更新的数据。
- 当前导航状态不持久化，因此 `System` 改为 `Available` 不需要迁移用户数据。
- Personal 与 System 的只读限制只由当前浏览上下文决定，不能污染同一逻辑 Skill 的 Library 副本。

## Testing And Acceptance

自动化测试至少覆盖：

- Personal 来源扫描 `~/.agents/skills` 下的有效 Skill。
- Personal 根目录缺失时返回空结果。
- Personal 不被计入 Installed。
- Personal 与 System 同名同 Hash 时合并，并保留两个来源。
- 同名不同 Hash 时保持两条记录。
- Available 的 All Sources、Personal、System 筛选结果正确。
- System 原有记录完整迁移到 Available 的 System 筛选。
- Available 详情按筛选上下文选择正确物理副本。
- Available 详情只读，但 Library 中同一逻辑 Skill 保持原有能力。
- Agent Copy 只作为补充来源显示，不进入 Available 来源筛选或计数。
- 测试使用临时目录，不依赖开发电脑真实 Home 内容。

产品验收至少覆盖：

- 侧边栏只显示 Library、Installed、Available，不再显示 System。
- Available 顶部来源筛选符合现有 macOS 原生筛选样式。
- Personal 与 System 来源标签容易理解。
- 空状态能解释当前来源范围。
- Available 与 Installed 数量可能重叠，但不会让用户误认为两者应相加。
- Available 页面不存在可修改源文件的操作入口。

## Delivery Boundary

V0.6.0 完成标准是 Personal 与 System 两类 Available 来源能够稳定扫描、合并、筛选和只读浏览，并且旧 System 能力完整迁移。

Plugin 来源作为后续 V0.6.x 独立阶段处理。进入该阶段前，必须先确认 Codex 提供的稳定插件清单或元数据接口；没有稳定来源时，不使用内部 cache 全量扫描作为正式实现。
